# Implicit and explicit in the Universe-1 experiments

Status 2026-10-09. This note separates what the experiments measure and state from what they assume without saying so. It was written from the documents, the result files and the code of this repository, and every implicit item below was checked against the files named for it; where a check changed the wording, the wording here is the checked one.

## 1. What the project explicitly measures

Universe-1 is a brute-force census of a tiny programmable machine. The machine state is one bit string; a step is a function on it; a program is 8 instructions of 4 bits (32 bits, 2^32 programs; 40 bits for the 5-bit crawler). The project fixes an instruction set (37 have been swept), places one 4-bit input x in the accumulator (16 inputs, unary) or x in the accumulator and y in memory word 1 (256 inputs, binary), zeroes everything else, runs every program for at most 256 steps (512 in exp10) and reads the accumulator. The vector of accumulator values over all inputs is the program's truth table, called a function. The number of distinct truth tables an ISA produces is its operator count; the smallest program id producing each table is its witness. That is the whole measurement, stated in docs/00_machine_model.md, docs/01_bruteforce_plan.md and docs/02_4byte_run.md, and every headline number is a count of distinct tables under that recipe: 1,829,051 unary and 24,684,247 binary for SWAP,ADD,NAND,SKZ (the champion), 8,533,818 unary for SWAP,ADD,NAND,JC, 142,263,973 champion functions over all steps 1..256 (exp09), 267,132,154 over 1..512 (exp10), 875,798,276 for JC over 1..256, 336.5 M to 367.5 M under the self-modifying layout L2 (exp06b).

Three further measurements sit on top of the counts. Naming matches tables against hand-written catalogs (352 unary and 740 binary tables in fast/map_functions.py; a separate Rust vocabulary with depth-2 compositions in results/maps/usability.md) and translation finds chains of programs that compose into a corpus of 55 functions (translate/REPORT.md; 44 of 55 reached). Self-copying under layout L2 counts programs that write all 8 code words into a non-overlapping window (141 copiers at 4 bytes, 16 persisting, 0 intact; 21,818 copiers at 5 bytes, 7,482 persisting, 3 intact at the moment of copying; results/exp06b_summary.md). Life runs genomes (32-bit programs) as cells on a torus under a world rule that reproduces a cell when its program returns 15 and kills by energy, age, random death or overwriting (docs/06_life_spec.md); 30 worlds have been run, none went extinct, and a convolutional world model predicts the next tick at 97.6 % in-world and 81.5 % on an unseen seed (results/life/worldmodel/REPORT.md). Everything was validated by agreement between engines (Python reference, C, CUDA, Vulkan, Rust) and by re-executing witnesses.

## 3. Implicit assumptions

Each item below is unstated in every document (the "where it hides" column names the code or sentence it lives in), was checked against the files, and would move a stated result if it changed. Severity is for the conclusions, not the raw counts.

## 4. Caveats that are already stated

The verifier checked a longer list of candidate assumptions and found these explicitly acknowledged. The reader does not need to re-raise them, only to know where they are.

- A function is A at step T; the value of a non-halting program at step 256 is exact and counted; a match does not imply termination (docs/03_function_map.md line 83; results/function-map/README.md line 9; results/README.md line 5; docs/07 lines 98-101).
- Only the accumulator is observed; flags, PC and memory are not (docs/00_machine_model.md lines 135-136; docs/01 line 48).
- Memory starts at zero with x in A and y in M[1]; "zero the rest" (docs/01_bruteforce_plan.md line 47; docs/06_life_spec.md lines 45-46).
- 256 is a multiple of the program length 8, so |F(T)| ripples with period 8 (results/exp09_summary.md line 11; docs/00 line 134).
- The operand field, not the opcode count, is the bottleneck; with o = 3 only A and M[1] are addressable (README.md lines 52-55; results/exp05_validation.md lines 43-55).
- Hashed keys for W=8 unary and W>=3 binary; collision estimate below 1e-9; hashed tables are recomputed from the witness (docs/02_4byte_run.md lines 29-31; results/witnesses/README.md lines 47-48; docs/03 lines 81-82).
- Hash-table overflow aborts the chunk and is reported (docs/02 lines 65-71; results/exp05_validation.md line 6).
- Witnesses are minimum numeric ids, not shortest or fastest; their step count is not the function's minimal cost; minimal T is the planned replacement (results/maps/README.md lines 4-6; results/function-map/README.md line 9; results/exp09_summary.md line 52; docs/08 lines 45-49).
- Rankings compare only the configured candidate ISAs and prove no global optimality; all runs use layout L3 (results/exp03_summary.md lines 41-42; results/exp05_summary.md lines 26-27).
- The exp05 variants are one-primitive ablations of the champion, and JZ/JC differ from SKZ in both flag source and jump target (cluster/isas_4byte.conf line 23; results/exp05_validation.md lines 41-43).
- Distinct-table count is the declared metric; constants and unnamed tables count as much as x+y; coverage and usability are separate named measures (docs/00 lines 3-4, 52-54; docs/01 lines 52-53; results/exp05_fable_review.md lines 28-29).
- The catalogs are hand-chosen and bounded; unmatched means unclassified, not novel; Python and Rust catalogs are not comparable; affine coverage at W=8 is sampled (results/function-map/README.md lines 3, 5, 11, 146; docs/03 lines 6-7).
- Translation is a bounded basis search with restricted bases and unequal depths across maps; stage boundaries reset memory and re-supply y; a chain costs p_k * 256 steps worst case; "256*" cells count as translated (translate/REPORT.md lines 4, 8-32, 105; docs/03 lines 79-80; translate/CLUSTER_RUN.md line 35).
- The emitted Rust tests use the same mapper for table and emulator; a failing test is a semantics mismatch to report (docs/04_translate_run.md lines 91-93; docs/03 lines 72-74).
- The W=8 unary result came from the five NVIDIA cards after the AMD timeouts (results/exp03_w8_o4.json runner_notes; results/exp03_validation.md lines 89-90).
- The step-256 champion label and the Life ISA decision rule are stated and the rule is not yet applicable (results/exp05_validation.md lines 60-63; results/exp05_fable_review.md Decisions 1-3).
- Steps 257..512 were validated on the Python reference (384/384 checks on 2^20 programs; fast/check_multi.py; commit b8975eb), although results/exp10_w4_o2_add_summary.md points to the wrong file for it.
- Every phase of a periodic orbit is a separate function; a program is a trajectory through function space (docs/07 lines 96-101; results/exp09_summary.md line 50).
- The linear extrapolation to about 400 M functions at step 1,100 is labelled as a straight-line extrapolation (results/exp10 lines 95-96).
- The 78x/103x/146x clock gain is usable only by an observer that picks T; the Life worlds at one fixed budget sample a thin slice (results/exp09_summary.md line 53; results/exp10 line 108).
- The binary union is deferred as open data debt (docs/08 lines 24-25; docs/09 lines 80, 94).
- HALT and fixed points freeze A for all later T and are counted at every later step (results/exp09_validation.md line 27; docs/08 line 13).
- Copier statistics come from the x = 0 run only; the NANO rule of at least 2 nonzero code words applies; the code+1 pre-fill is a scoring device; "intact" is at the moment the copy completes, not at step 256; "persists" is at step 256; the first-copy moment is defined by an external comparison, not an instruction (results/exp06b_summary.md lines 5-6, 46-47, 61-65; sim/machine_l2.py lines 9-13).

## 5. The five tests that would most change the conclusions

Ranked by how much stated conclusion they put at risk per GPU-hour.
